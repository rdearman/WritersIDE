## Domain and storage contracts

- A link is directed and typed. Its endpoints are `(kind, stable UUID)` pairs; titles and paths are display data only. Backlinks query the reverse index over the same canonical link row.
- Passage anchors belong to a scene and record UTF-8 byte offsets, exact quote, context, content hash and an explicit state. An edit must not silently retarget an anchor; until re-anchoring is implemented, stale anchors require review.
- Transclusion and inclusion are distinct link kinds. They never duplicate source text. The initial database rejects cycles among include/transclude edges. Rendering and manuscript export must state whether referenced content is expanded.
- Saved query filters are typed records, combined with AND semantics in filter order. Query evaluation is a read-only view ordered by current manuscript placement; absent placement sorts after placed scenes. Saving a query or refreshing results never persists a new placement.
- Full-text indexes are rebuildable caches. SQLite rows/files remain authoritative.
- Reading annotations refer to immutable source fingerprints plus stable passage anchors. When source bytes change, annotations become unresolved/reviewable rather than being applied to changed text.
- LLM output is an untrusted proposal with source evidence and provenance. Approval is an explicit application operation; inferred facts remain separate from author-defined records.
- Pipeline stages declare inputs, outputs and dependencies. A failed or skipped stage is visible and cannot be reported as a successful complete manuscript build.

### Reading rendering milestone

The Reading workspace visually marks current highlights (yellow background) and notes (cyan underline) directly over extracted text. Rendering is a projection: it never changes the source document, and annotations with stale or invalid anchors are not painted. The terminal regression test checks the styled span and direct passage navigation.


### Analytics workspace milestone

The terminal Analytics workspace now presents the complete scene heatmap, named character interaction counts, subplot gap locations, uncertain chronology pairs, and budget redistribution suggestions. All output is a read-only projection; budget suggestions are marked as previews and never alter scene targets. A regression test exercises these report sections and verifies no target mutation.


### Chronology timeline milestone

The terminal Timeline workspace now orders scenes by story-time values, displays start/end ranges for approximate and bounded values, places unknown dates last, and opens the correct scene through its stable ID. Workspace list navigation now follows the actual visible rows, including expanded analytics reports. Event-level timeline interaction and visual overlap grouping remain incomplete.


### Story-event timeline milestone

Scene and typed event records appear together in the terminal Timeline workspace, sorted by canonical time for display with unknown intervals last. Event start/end uncertainty and original source-time text remain visible. The `event-time` command creates exact, bounded, approximate, or unknown event times. Selecting an event navigates to its Story Bible row. Mixed timeline ordering and persistence are regression-tested.


### Saved-query terminal collection milestone

Saved queries now run as a live virtual collection in the terminal Search workspace. Results refresh from current story data, retain manuscript order, and do not replace the application's full scene listing. Enter opens the selected matching scene by stable ID; `query-clear` returns to the complete scene list. Regression coverage checks dynamic membership after metadata changes and verifies scene order and identity are preserved.


### Story entity navigation milestone

Project-wide search and reading links now navigate characters, locations, plotlines, events, and issues to the correct record row. Enter inspects the selected record rather than opening an unrelated scene. The Story Bible supports creating and listing locations, and entity creation selects the new record. Terminal tests cover each search destination and prevent scene-index confusion. Full character/worldbuilding editing forms remain incomplete.


### Transclusion-aware compilation milestone

The incremental processing pipeline now supports opt-in scene transclusion expansion. CLI `process <project> --expand-transclusions` and terminal `:process-expand` generate a derived compile artifact while leaving canonical manuscript files untouched. The compile cache fingerprints the selected mode. Integration tests verify expansion and unchanged source text.

### Imported Reading-document inclusion milestone

Typed story links now accept Reading document IDs as document endpoints. Migration 0009 preserves existing links while adding Reading IDs to the endpoint constraints and source-existence checks. Compilation resolves extracted text only after verifying the imported source fingerprint, then includes it in the derived view without editing source bytes or annotation records. Storage and app tests cover stable backlinks, scene-to-reference inclusion, cycle checks across document types, and source-safe compiled output.


### Issue #8 command registry and shortcut foundation

A typed terminal registry now provides stable command IDs and metadata for workspace navigation, save, help, Compile and parameterized project actions. Keyboard workspace dispatch, palette entries and hierarchical menu choices use the shared typed dispatcher. Ctrl+/ (plus Ctrl+_ where emitted by terminal protocols) and F10 route to the main menu. F10 has been removed from the default Research workspace binding; Research remains accessible through Tab/BackTab. Ordinary `/` inserts into the manuscript editor. The popup preserves editor state and surfaces disabled-action reasons.

The menu milestone now renders and navigates a category popup from the central command registry, preserves editor state on open/close, routes arguments into the command prompt and reports disabled reasons for context-sensitive actions. The menu has File, Edit, Insert, Scene, Plot, View, Compile, Tools and Help categories. Project-local `[commands]` keybindings map modified chords to stable registry IDs; startup rejects duplicate/reserved chords, unknown commands and commands requiring arguments. Bare printable keys remain manuscript input. Remaining Issue #8 work includes an interactive binding editor, comprehensive reporting for collisions with every context-specific editor action, enhanced keyboard protocol negotiation and expanded contextual availability policy. Ctrl+/ remains terminal-dependent; F10 is the fallback.

The terminal registry also covers parameterized palette commands with stable IDs, categories, descriptions, aliases, and argument contracts. All registered palette invocations and configured command shortcuts pass through the central dispatcher. The shortcut loader validates reserved keys and command identity; a visual binding editor, complete shortcut conflict report, availability-policy expansion and CLI registry reuse remain follow-up work.


### Evidence-checked extracted-knowledge approval milestone

Approved knowledge claims now persist in schema migration 0007 with candidate kind/name/statement, optional story-time text, stable source identity, source fingerprint/length, exact quoted passage and byte offsets, model, and approval time. Promotion rejects stale sources and invalid evidence offsets, is idempotent for a claim already promoted from the same evidence, and updates the rebuildable FTS index. The CLI `approve-extraction <project> <proposal-json-file> <claim-index>` and terminal `approve <proposal-json-path> <claim-index>` promote one claim after explicit author action. The `knowledge` CLI command, Story Bible rows, and project search expose approved records and their evidence. Tests cover scene/reading references, source immutability, staleness, persistence, idempotency, indexing, and terminal navigation. Proposal claim editing/retraction and promotion into entity-specific character/event records remain deferred.


### Selective dependency-aware processing milestone

The pipeline now exposes `run_selected`, adding transitive dependencies for requested stages and reporting unrequested stages as `NotSelected`. Failed dependencies still mark dependent stages `Skipped`; failures remain visible. Stable stage names support CLI `process --only` and terminal `process-only`/`process-expand-only`. The full `process` command remains unchanged. Tests cover Export's Compile dependency, cache reuse, excluded stages, dependency failure, stable stage names, CLI validation and terminal invocation. Declarative profiles and richer build configurations remain deferred.


### Provisional extraction review milestone

Authors can list and inspect proposal files and their candidate claims, including evidence excerpts and provisional/approved/dismissed status. A dismissed claim remains in its provenance record, cannot be promoted, and does not create a canonical story fact. Approval still requires explicit action and current source/evidence validation. CLI and terminal updates are project-local, hash-checked, atomically replaced, and reject stale proposal versions. Previous proposal JSON without a dismissed field loads as provisional. Live Ollama compatibility and entity-specific candidate promotion remain unverified.


### Character profile persistence and editing milestone

Migration 0010 persists the SRS character profile fields: full and preferred names, aliases, description, background, goals, motivations, secrets, internal/external conflicts, and status. Aliases are case-insensitively unique per character. Profile content and aliases are searchable. CLI profile inspection and field/alias updates are available; the terminal command registry exposes profile inspection and editing. Migration, persistence, validation, search, application service, and terminal workflow tests pass. Character-to-character relationship editing and first/last appearance summaries remain incomplete.


## Issue #21 — WYSIWYM semantic document foundation

The canonical prose choice remains portable UTF-8 Markdown, with story structure and semantic metadata external to prose. The new `story-document` prototype parses Markdown structure and inline semantics into a versioned source-preserving tree with UTF-8 byte ranges and content fingerprints. The dependency-aware compiler now constructs a renderer-neutral ordered `CompileIr` with stable content-unit and source-segment identities and output-to-source byte mappings; Markdown compilation passes through this IR. The prototype covers headings, paragraphs, emphasis, quotations, lists, code blocks, tables, footnotes, links, images, and task markers through pulldown-cmark 0.9.6. Synthetic UTF-8/round-trip/source-map tests pass. There is no author-provided formatted chapter fixture in the repository, so source syntax coverage and encoding decisions are not frozen pending real-chapter fidelity review. Full semantic inset persistence and print/digital renderers are deferred.

## Issue #20 — Fiction and nonfiction content model foundation

Projects now persist a book type separately from an optional template identifier. The built-in template catalog identifiers are Blank Fiction, Novel, Short Story, Blank Nonfiction, and Non-fiction Book. Migration 0011 adds typed direct-prose content units for front matter, section bodies, chapter bodies, and back matter; migration 0012 records the selected template identifier. Chapter body text has its own stable UUID, Markdown file, hash, word count, search projection and durable write/recovery journal. It can be saved, reopened, relocated, conflict-inspected, and compiled without creating a scene. The initial composition rule emits a structural node's direct body before its child content and scenes; front matter precedes the outline and back matter follows it. Recovery failpoint tests cover pre-intent cleanup, intent, pre/post replacement and post-metadata commit; conflict tests preserve both versions and require an explicit prepared/external choice. Declarative author-template editing/import/export, detailed template prompts and mixed body/scene ordering remain follow-up work and are not claimed as implemented.

## Issue #11 — Local Git snapshot foundation

A new `story-git` crate supports project-local repository initialization, named snapshots, history, diffs, and restore-to-new-project. A SQLite `BEGIN IMMEDIATE` writer barrier reconciles pending scene/content-unit journals, rejects unresolved write conflicts, generates deterministic `snapshots/database.sql`, validates it in a fresh SQLite database, and holds the barrier through Git staging/commit. SQL includes canonical metadata, relationships, migration history, and import provenance plus empty recovery-journal schemas; it excludes transient journal entries, local scene snapshots, rebuildable search projections and FTS index rows. Git stages only app-owned project paths and refuses to consume unrelated staged files. Live databases, WAL/SHM, runtime state, exports, temporary files and common secrets are ignored. `git-restore-new` reconstructs an isolated project from a commit's owned files and metadata dump, validates it, and refuses to overwrite an existing destination. `git-restore-scene` selectively restores one current scene's prose through the durable write journal after taking a consistent pre-restore project snapshot; it never changes structure or metadata. Optional automatic snapshots use a project-local interval from 1 to 10080 minutes and run only while the terminal application is open; they use the same writer barrier, skip empty commits, and report failures. Tests cover repeatable no-op snapshots, SQL byte determinism/replay/integrity, consistent prose/metadata commits, path safety, live DB exclusion, unrelated staging, and restore/reopen/relocation. Selective historical structural/database restoration, automatic snapshots outside a running terminal session, remote operations, and restoration from commits created before metadata dumps remain incomplete; Issue #11 is not yet fully satisfied.

### Issue #4 — Multilingual editing foundation

Terminal manuscript cursor columns use extended grapheme clusters for navigation, insertion, deletion, and selection, so combining marks and emoji sequences are not intentionally split by editor actions. Scene and content-unit counts use a project-selected deterministic policy. `unicode-words` (default) counts Unicode word boundaries; `script-graphemes` counts grapheme clusters in CJK and selected unspaced-script ranges individually while counting other scripts by Unicode word boundaries. Regression fixtures cover British English, Italian, French, Korean syllables, decomposed Hangul Jamo, and decomposed Latin accents. This is explicitly a writing-budget convention, not dictionary-based linguistic tokenization. Scene search/indexing uses SQLite FTS5 `unicode61 remove_diacritics 1`, which provides Unicode simple case folding and accent-insensitive matching in a search-only index; canonical manuscript text is never normalized or rewritten. The policy is intentionally language-independent, so locale-sensitive cases such as Turkish casing and accent-sensitive exact search remain open. CLI `word-count-policy` and terminal `project-word-count-policy` update the project policy and atomically recalculate stored content-unit counts; scene counts, analytics, editing statistics, challenges, and processing reports use the policy. Script-specific dictionary tokenizers and spellchecking beyond local external tools remain open.

### Issue #12 — Scoped find and replace foundation

Core search provides literal Normal, Extended escape and Rust-regex modes with UTF-8 byte ranges; regex replacement supports captures and treats `^`/`$` as line anchors. The bottom panel defaults to Normal/current-scene, remembers the last text/replacement/case/whole-word preferences and up to 50 distinct successful queries, and resets mode and scope on opening. F11/F12 browse older/newer queries and restore the in-progress query; `search.history-older` and `search.history-newer` can be rebound in project keybindings. Results show scene, line and context; F3/Shift-F3 navigate. Replace preview supports per-match and per-scene selection. F9 replaces the next current-scene match as an undoable editor edit. Terminal multi-scene apply persists a group recovery record before writing, detects divergent external edits on startup, and restores all targets only when the full state is unambiguous. The last successful scoped replacement has a durable one-step undo via Ctrl-Z or the Edit menu; a pre-change Git snapshot is taken when the project already has Git history. CLI `replace-apply` now has equivalent durable group recovery, conflict preservation, optional Git pre-snapshot, and hash-checked `replace-undo`; `replace-recover` exposes pending-group recovery explicitly.

Definition lookup (`tags`) resolves stable IDs for scenes, chapters and named story entities, including character aliases; `refs` searches raw prose and labels matches as textual references rather than participation. Search results include a return-to-previous-position stack. `tags-export` generates an Emacs TAGS file and a Markdown symbol index under `.writers-ide/tags`; definitions include stable IDs and scene source paths, and the TAGS offsets point to those index entries. This provides external editor navigation to the generated index, not directly into structured database records. Confirmed entity mentions can now navigate to their validated manuscript passage and are clearly distinguished from narrative participation. A continuously maintained dedicated symbol index, Ctags output and richer semantic-reference navigation remain open. CLI group recovery/undo is implemented; Vim substitution aliases are available for the supported substitution syntax.

### Issue #13 — Split reference panes and outline narrowing foundation

The terminal editor supports scene, research-document, character, location, plotline, timeline, project-search, compile-diagnostic and object references with session-restored stable identities and scroll offsets. All open buffers render simultaneously in adaptive side-by-side panes on wide terminals and stacked panes on narrow terminals. `reference-layout auto|horizontal|vertical` selects automatic, side-by-side or stacked editor/reference panes; Ctrl+arrows resize the split. `reference-toggle` hides and restores reference panes while keeping their buffers open. Layout choices restore with the session. Ctrl-Tab changes focus, arrow/Page keys scroll read-only buffers, `reference-next`/`reference-prev` changes the selected buffer and `reference-close` closes it. A scene card can follow the active scene via `reference-follow-card` or be pinned via `reference-pin`; the mode is labelled and restored on restart. Opening the currently edited scene with `reference-scene <scene-uuid>` gives a second view of the same editor buffer, with its own scroll and cursor. Ctrl-Tab switches between the two cursor positions, and edits, undo and saves operate on the shared prose. Ctrl-G focus mode hides all surrounding panes and application chrome to leave the prose editor across the content area. `narrow <chapter-uuid>` filters the scene list without changing manuscript placement; `widen` restores it, and narrowing is persisted. Missing or deleted sources use the existing stale-reference handling. A general rearrangeable window manager, maximizing reference views, editable structured entity views, independent view selections and the remaining Issue #13 acceptance items are still open.

### Issue #18 — Professional editing and mechanical proofing foundation

The editor has session-restored reference buffers, idle autosave through the optimistic journal, visible save conflicts, personal anchored comments, manuscript snapshots, selective hunk restoration, and bounded in-memory undo/redo. A deterministic read-only proofreader reports repeated adjacent words, double spaces and spaces before common punctuation with UTF-8 byte ranges; it is available through CLI `proofread <project> [all|scene-uuid]` and terminal `proofread [all]`. It never changes prose. Configurable rule sets and local Aspell dictionaries are available; `spellcheck LANGUAGE [PROJECT-WORDLIST] [ASPELL]` in the terminal scans scenes and chapter prose without modifying them. `review-merge` presents base/local/reviewed text side-by-side and `review-resolve` accepts an explicit choice per hunk, leaving unresolved ranges unchanged.

The terminal editor now performs a two-second idle autosave through the existing optimistic, journaled save path. On a detected conflict it keeps the unsaved buffer and stops automatic retry until further user activity, avoiding repeated blind writes.

A sustained persistence test now performs 24 successive writes of a large Unicode scene, reopens the project every six revisions, and verifies final text, stable scene identity, content hash, and Unicode word count.

A terminal editor stress test routes 120 Unicode paragraphs through the real key handler, saves and reopens every 30 paragraphs, restores session cursor state, and verifies exact prose, hash and word count. It found and fixed a cursor restoration issue where reopening prose ending with a newline discarded the final empty editor row and could overwrite the preceding paragraph. This repeatable integration test complements the storage-level journal stress test; a multi-hour manual terminal session remains a release exercise.

The manuscript editor now supports a bounded 100-step in-memory undo/redo history per open scene, including cursor and selection restoration. Ctrl-Z undoes; Ctrl-Y and Ctrl-Shift-Z redo. Undo history is session-local, while durable snapshots remain the persistent revision mechanism.

### Issue #7 — Manuscript compilation formats

Compile IR renders structured section/chapter hierarchy, manuscript prose, and UTF-8 source ranges. `writers-ide compile <project> <text|markdown|html|epub|docx|pdf> [output-path] [--expand-transclusions]` provides in-process plain-text and Markdown output and uses a local Pandoc installation for HTML, EPUB, and DOCX. PDF additionally requires local LuaLaTeX. The terminal command palette exposes `compile-format` with the same output choices. Each export writes an atomic JSON source-map sidecar; offsets identify entities and byte ranges in the canonical UTF-8 Compile IR Markdown stream and do not claim final layout positions or PDF page coordinates. Export generation is offline and does not change manuscript sources. Renderer templates, named book designs, PDF typography/publishing diagnostics, and visual source mapping remain Issue #21 work.

### Issue #21 — LuaLaTeX and book-design foundation

The PDF renderer uses a project-local temporary TeX cache and typed `trade-paperback`, `hardback`, `manuscript`, `nonfiction`, and `technical-academic` profiles with fixed Pandoc layout variables for paper size, margins, document class, font size, and line spacing. CLI and terminal compile commands accept `--design=<preset>`. Versioned TOML book-design profiles are also accepted with `--design-file=<project-relative-path>`; document class, paper size, class options, geometry, font size, line spacing, and safe font-family names are validated before renderer invocation. Profiles can select main/sans/monospaced fonts, page style, section numbering and a project-local custom LuaLaTeX template. Font availability is determined by the local LuaLaTeX installation. An example style profile is in `templates/book-design/compact-trade.toml`. `latex`/`tex` is a direct Compile format; PDF renders retain the generated `.tex` source and LuaLaTeX log as sidecar files alongside the requested output. Renderer subprocesses run in a temporary working directory, keeping generated files out of manuscript/source directories. Deterministic publication diagnostics identify missing project title, empty manuscripts, empty content units, and likely draft placeholders (`TODO`, `FIXME`, `[INSERT`, `Lorem ipsum`) without mutating story data (`compile-check` in the CLI). ### Issue #6 — Manuscript import foundation

The import crate now performs read-only DOCX, RTF, ODT, and EPUB inventory into a staging model with stable source-item identifiers, source fingerprint, extracted text, and explicit formatting/media loss warnings. `inspect-manuscript` emits the inventory without touching the source. `import-manuscript` creates a new project directory only, stores imported units as chapter/scene manuscript files, records import runs/source items/field provenance, and emits `exports/import-report.json`. No real editorial documents were available for compatibility claims.

### Issue #19 — Editorial merge foundation

The review layer inventories DOCX insertion/deletion markup and comments with author/date/comment IDs (`review-inspect`), and performs a line-oriented three-way merge from a base manuscript, current local scene, and reviewed external text. `review-docx <project> <scene-uuid> <base-file> <review.docx> accept|reject` and the terminal `review-docx` command derive accepted or rejected prose from DOCX tracked changes and merge it through the normal optimistic manuscript journal. Non-overlapping edits merge automatically; overlapping edits return explicit base/local/external conflict regions and leave canonical text unchanged. `review-resolve` and terminal `review-resolve` accept a comma-separated Base/Local/External choice for each conflict range in the order reported; disjoint edits remain applied, and the result is saved through the optimistic journal. The terminal now displays Base/Local/Reviewed columns beside the canonical scene; dirty buffers block review rather than displaying stale text. Source DOCX files remain read-only. DOCX review inventory now anchors Word comments to the first paragraph touched by their range markers; comments lacking a source marker remain explicitly unanchored. Inline comment display, editable conflict text, and finer-grained character-level resolution remain incomplete.

The browser scene collection now supports read-only text, status, character and plotline filters over stable-ID plan data while preserving manuscript order. Scene start/end chronology can be edited in the browser using exact, unknown, approximate or bounded signed ticks, with domain validation and no change to manuscript placement. # Advanced inspection additions (Issue #15)

Saved query expressions support confirmed character presence separately from mentioned-only references, and can combine character, location, event, chapter, and literal manuscript-text filters. Missing relations are not presented as confirmed absence. Deterministic event-order and recorded-knowledge assertions return PASS, FAIL, UNKNOWN, or SKIP with evidence; missing or uncertain data cannot produce a PASS. Local project Git history supports literal passage search with introducing diffs and line-level provenance. Expanded location/event coverage matrices and a general assertion/watchpoint language remain deferred.

Character absence is now an explicit scene relationship with notes. Unrecorded participation remains unknown, while an explicit absence query matches only author-entered records. Storage triggers reject simultaneous confirmed participation and explicit absence; mention-only relationships may coexist with absence. Character coverage excludes mention-only records.

Saved queries now include typed scalar custom-metadata equality predicates keyed by field UUID, with validation against the declared field type and enum options. The CLI and terminal accept `meta=FIELD-UUID:VALUE` filters; prefixes distinguish non-text types. Entity-reference-list membership queries are not yet supported.

Events can now have explicit `precedes` and `requires` dependency edges with notes. SQLite rejects self-links and dependency cycles, including direct SQL attempts. Inspection compares the recorded end and start story-time intervals and keeps ambiguous/missing dates UNKNOWN; manuscript disclosure order does not substitute for fictional chronology.

Inspection queries now filter scenes by included membership in a named assembly and by any issue status. Coverage requirements now include POV, location and event, using stable entity relationships; mention-only character records remain excluded from presence coverage. These analytical projections do not reorder or mutate manuscript content.

Entity-reference-list custom fields can now participate in saved scene queries through `meta-contains=FIELD-UUID:KIND:ENTITY-UUID`. The field's declared type/reference kind and the referenced entity are validated before saving; query results remain dynamic and read-only.

Chronology queries now offer explicit definitely/possibly before/after predicates over bounded scene start-time intervals. They use interval bounds, retain strict cutoff semantics, and exclude unknown or insufficiently bounded times rather than guessing. The original nominal-time filters remain for compatibility.

Saved-query results can be explained with stable scene and related-entity evidence, including current text hash, characters, plotlines, events, locations, issues and custom metadata references. Positive literal text filters add verified UTF-8 byte ranges in the canonical scene file and field-relative byte ranges for title/synopsis matches. The CLI `query-explain` and terminal `query-evidence` commands require the scene to remain a current match and refuse stale manuscript passage offsets after an external edit. General full-text-search expressions and non-scene search results do not yet have exact source maps.

Authors can now persist enabled/disabled incompatibility rules for location pairs. The continuity inspector compares scenes sharing a character and reports definite overlap, possible overlap, or unverified timing separately. The rules are project-local and can be managed and evaluated through CLI and terminal commands.

Event dependency assertions (`precedes` and `requires`) can now be added, listed, have their notes updated, removed, and evaluated through both CLI and terminal commands. These use stable event IDs and existing SQLite cycle/reference constraints. Evaluation remains uncertainty-aware and returns unknown when the chronology is insufficient. A general configurable assertion/watchpoint model and passage-level source maps for broad text search remain open.


Custom-metadata saved queries now support field existence, escaped text containment, and typed numeric comparisons through stable field IDs. CLI and terminal syntax includes `meta-exists=FIELD`, `meta-text=FIELD:TEXT`, and `meta-number=FIELD:OP:int|decimal:VALUE`; field types and finite numeric operands are checked when saved. Integer comparisons remain exact SQLite integer comparisons; decimal comparisons use the current decimal field storage precision.
